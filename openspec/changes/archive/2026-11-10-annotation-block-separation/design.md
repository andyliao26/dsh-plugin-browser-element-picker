# Design

## Context

`inject()` 有三条注入路径：引用 chip（`insertReference`）、引用节点（`insertQuote`）、纯文本追加（`requestDraftInitialization`）。前两条由 composer 决定边界——`insertReference` 的实现是「chip 节点 + 一个尾随空格」，所以两段块之间只有一个空格。插件无法改这条落点规则，只能改自己提供给它的文本。

## Goals / Non-Goals

**Goals:**

- 多段标注在最终提示词里有清晰边界，且单段标注的开头保持干净。
- 三条路径产出同一段文本。

**Non-Goals:**

- 不改 composer 的插入规则、不改块内部的既有排版。
- 不试图识别「上一段是不是标注」：插件拿不到 composer 的语义内容，只能看插入点。

## Decisions

### 1. 用插入点判断，而不是猜内容

`shell.caretSpan()` 是既有契约里就能拿到的（`inject()` 本来就用它构造 chip 的 span）：`start > 0` 说明插入点之前已经有东西——可能是上一段标注，也可能是用户自己写的话。两种情况都该分开，所以这条判据不需要认识内容，也不会因为用户删掉 chip 而失效。

`start === 0`（空草稿开头，或光标被放到最前）时不加前缀：单段标注的提示词保持现在的样子。

### 2. 前缀是「空行 + 分割线 + 空行」

`\n\n---\n\n`：块的最后一行与下一块的首行之间出现一条 `---`，上下各留一个空行。这与块内部「评论前用 `---` 分隔」的既有写法同一套视觉语言。

前缀只加在**块文本**上，不进 chip 的 `label`——chip 在输入框里仍然显示「标签 + 评论」的短标签。

**考虑过并放弃：**

- *把 `---` 追加到每段块尾*：最后一段会多出一条悬空分割线。
- *让 chip 之间由 composer 加空行*：`insertReference` 的落点规则不接受外部控制，且那属于宿主契约变更。

## Risks / Trade-offs

- **用户先写一句话再标注，也会多一条分割线** → 语义上正确（标注是独立小节），且空草稿不受影响；若不想要，删掉那两行即可。
- **`caretSpan()` 不可用** → `draftSeparator` 返回空串，行为退回旧版，不影响注入本身。

## Migration Plan

`0.11.1` → `0.12.0`，`link:` 依赖，重载生效；回退即回退版本。已存在的草稿不受影响，只影响之后的插入。

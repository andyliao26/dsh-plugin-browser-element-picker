# Design

## Context

`formatAnnotation()` 组装要求段时是「空行 + `---` + `**修改要求:** {comment}`」。上一版给「插在已有内容之后的块」加了 `\n\n---\n\n` 前缀，于是多段标注的提示词里会出现两条紧邻的分割线，视觉上重复。

## Goals / Non-Goals

**Goals:**

- 要求段与目标列表之间靠空行分开，不再靠分割线。
- 分割线在整份提示词里只有一个用途：分隔两段标注。

**Non-Goals:**

- 不改块与块之间的分隔方式。
- 不改 `**修改要求:**` 这个标签本身。

## Decisions

### 1. 只删 `---`，保留空行

空行是必需的：Markdown 里没有空行时，`**修改要求:** ...` 会被并进上面那条目标行，成为同一段落。删掉 `---` 只影响版式，不影响可解析性。

### 2. 同步文档与断言

块结构在 `AGENTS.md` 的契约段里写着，README 有两处示例；测试用精确字符串比较块文本。三者一起改，避免文档与实现再次漂移。

## Risks / Trade-offs

- **已有用户习惯「`---` 之后是要改的内容」** → 空行 + 标签仍然清晰；模型看到的语义没有变化。
- **历史 changelog 描述会被读成「现在也有 `---`」** → 新增 0.13.0 条目说明变化，旧条目保持历史原样。

## Migration Plan

`0.12.0` → `0.13.0`，`link:` 依赖，重载生效；回退即回退版本。只影响之后插入的文本。
